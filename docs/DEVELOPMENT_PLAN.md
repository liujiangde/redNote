# RedNote 后续开发计划

本文档记录 2026-06-01 的项目现状和后续开发路线。当前仓库是一个“小红书 Lite”全栈骨架：前台 Feed、搜索、发布页、笔记详情、用户主页、管理后台、本地数据库、对象存储、Redis、AI embedding 和推荐评分都已经有基础代码。M1 已完成，主要页面已切换到 Prisma 查询，`src/lib/mock-data.ts` 仅作为开发兜底和 UI fixture 保留。

## 产品目标

RedNote 的目标是做一个偏生活方式内容的 C 端社区，核心闭环是：

- 用户可以注册、登录、编辑个人主页。
- 创作者可以发布图文笔记、上传图片、添加标签、保存草稿。
- 普通用户可以浏览推荐流、搜索内容、点赞、收藏、评论、关注作者。
- 管理员可以审核内容、处理举报、查看运营指标。
- 搜索和推荐可以结合标签、互动、时间新鲜度、关注关系和语义向量。
- Web 和移动端 App 共享核心业务能力，支持多语言、多地区内容展示和跨端通知。
- 长期对标小红书级 App 时，需要进一步覆盖视频、直播、电商交易、私信、创作者工具、商业化、风控和数据运营。

## 对标小红书的产品拆解

对标小红书时，本项目只参考公开产品能力和业务结构，不复制品牌、视觉资产、专有算法或具体运营内容。能力拆解按下面几个产品域推进：

- 内容发现：推荐瀑布流、关注流、同城/附近、话题、地点、榜单、活动专题。
- 内容创作：图文、视频、封面、标签、话题、地点、草稿箱、编辑器、发布质量提示。
- 生活搜索：搜索建议、热搜、历史搜索、分类搜索、搜索结果解释、语义召回。
- 社区互动：点赞、收藏、评论、回复、关注、分享、@ 提及、私信、通知。
- 创作者成长：创作者中心、数据看板、成长任务、账号等级、认证、商业合作入口。
- 内容电商：商品卡、店铺、购物车、订单、支付、售后、优惠券、达人带货、直播带货。
- 信任和治理：内容审核、举报、申诉、账号风控、反刷量、未成年人保护、隐私合规。
- 数据运营：曝光、点击、停留、搜索、互动、交易、审核、推荐反馈、A/B 实验。

阶段策略：

- M1-M6 先做社区 MVP：账号、发布、浏览、互动、搜索、审核、测试和生产化。
- M7-M9 做跨端、国际化、埋点和运营基础。
- M10-M12 再推进接近小红书级 App 的原生体验、商业化、直播、风控和数据平台。
- 不在早期堆复杂商业化和高并发架构，但从 M1.5 起必须预留 API contract、分页、事件入口、权限边界和上传边界。

## 里程碑

### M0：基础骨架稳定

状态：已具备雏形，需要补齐验证。

- 保持 Next.js 16 App Router 结构稳定。
- 本地 Postgres、pgvector、Redis、MinIO 初始化脚本可重复运行。
- Prisma schema 覆盖用户、笔记、图片、评论、互动、关注、通知、举报、审计日志、embedding。
- 前台和后台页面保持可访问，不依赖真实登录态也能展示 MVP。

验收标准：

- `pnpm install`、`pnpm db:setup`、`pnpm prisma:migrate`、`pnpm storage:bucket`、`pnpm prisma:seed`、`pnpm dev` 能完成本地启动。
- `pnpm lint` 和 `pnpm typecheck` 通过。

### M1：页面从 Mock 数据切换到数据库

状态：已完成。

- 将首页 Feed 改为从 `notes`、`note_images`、`users`、`tags` 读取已发布笔记。
- 笔记详情页按 `noteId` 或 `slug` 查询真实数据，补充浏览数递增策略。
- 用户主页按 `handle` 查询用户资料、作品列表、关注和粉丝统计。
- 后台笔记、举报、用户页面接入 Prisma 查询。
- 为列表查询抽出服务层函数，避免页面组件直接堆叠复杂查询。

验收标准：

- 页面主流程不再依赖 `demoNotes`。
- 空状态和 404 已覆盖核心前台、后台列表。
- 种子数据可以驱动前台和后台页面。

### M1.5：跨端基础与工程护栏

状态：基础版已完成，移动端完整 API 将在 M2-M4 随业务闭环继续补齐。

优先级：高。建议在 M2 大规模接入表单、上传和互动前完成。

- 定义 Web/App 共用 API contract：统一响应结构、错误码、分页格式、鉴权头、DTO 命名和版本策略。
- 为核心能力预留 Route Handler 或 BFF API：Feed、详情、搜索、登录、注册、发布、上传、点赞、收藏、评论、关注、通知。
- 明确认证边界：Web 继续使用 NextAuth session，移动端单独定义 token/session 持久化和刷新策略，避免 App 依赖 Web-only cookie 假设。
- 明确 RBAC 权限边界：普通用户、管理员、超级管理员分别能访问和修改哪些资源。
- 建立 i18n 前置骨架：message dictionary、locale-aware formatter、默认语言和后续 URL locale 策略，新增页面不再继续扩散硬编码中文。
- 提前规划数据模型扩展：用户语言偏好和地区、笔记 locale/region、移动端 device token、上传资源状态、举报处理人和处理历史、内容软删除或隐藏字段。
- 统一本地服务启动方式：优先补 `docker-compose.yml` 或 `pnpm services:up`，同时启动 PostgreSQL + pgvector、Redis、MinIO。
- 提前建立最小质量门禁：GitHub Actions 运行 `pnpm lint`、`pnpm typecheck`，并逐步加入注册、登录、发布、权限保护的 smoke test。
- 建立 pgvector migration 审查规则：Prisma 生成的 migration 涉及 `note_embeddings`、向量索引或 `DROP INDEX` 时必须人工确认。
- 明确分页和性能基线：Feed、搜索、后台列表使用 cursor 或稳定分页，浏览量递增需要节流或去重策略。
- 只做高并发架构预留，不在 MVP 阶段提前堆复杂性能工程：服务分层、分页、事件入口、上传边界、权限边界现在要定好；读写分离、分库分表、复杂缓存和队列可后置。

验收标准：

- 有一份明确的 API contract 草案，Web 和未来 App 都按同一套 DTO、错误码、分页格式对接。
- 认证、管理员权限、移动端 session 策略有明确实现边界。
- 新增用户可见文案可以从字典读取，日期、数字、相对时间有统一 formatter。
- 本地服务可以通过一组命令启动，Redis 和 MinIO 不再只停留在文档说明。
- CI 至少覆盖 lint、typecheck；pgvector 索引迁移不会被无意删除。
- 高并发相关的扩展点有设计约束：列表接口可分页，计数和事件可替换为 Redis/队列聚合，搜索和推荐可替换底层实现而不改变前端 contract。

### M2：认证、注册和发布闭环

状态：基础版已完成，后续可继续增强移动端认证、上传 CORS/清理和草稿管理。

优先级：高。

- 接通登录表单和 NextAuth Credentials。
- 实现注册接口或 Server Function，校验邮箱、密码、handle 唯一性。
- 发布页改为真实表单，支持标题、正文、标签、图片上传、草稿和发布状态。
- 为创作链路预留小红书式内容结构：话题、地点、封面、可见范围、内容质量提示和发布前预览。
- 使用 MinIO/S3 预签名 URL 上传图片，并写入 `note_images`。
- 保护 `/publish` 和 `/admin`，管理员页面按角色授权。

验收标准：

- 用户能完整注册、登录、发布笔记、在个人页看到作品。
- 未登录用户访问发布页被引导到登录。
- 非管理员访问后台被拒绝。
- 新发布笔记至少能携带标题、正文、图片、标签和状态，后续可平滑扩展话题、地点和封面。

### M3：互动和社区关系

状态：基础版已完成，M3.1 通知中心、评论区、互动风控、移动端互动 API 和评论治理基础版已完成。已接通点赞、收藏、一级评论、二级回复、一级评论分页、关注、通知写入、通知中心页面/API、未读数、已读、分页、互动限流、目标冷却、重复评论保护、`/api/v1` 互动写接口、评论删除/举报和后台隐藏/驳回；高级风控和屏蔽能力进入 M3.1 后续/M5 增强。

优先级：高。

- 实现点赞、收藏、评论、回复、关注。
- Web 笔记详情页展示当前用户点赞/收藏状态、一级评论列表和评论发布入口。
- 用户主页展示关注/已关注状态，并支持关注或取消关注。
- 点赞、收藏、评论、关注通过 `src/lib/community-service.ts` 统一处理目标校验、写库、通知和风控；Web 页面由 `src/lib/community-actions.ts` 处理登录跳转和页面刷新，移动端通过 `/api/v1` Route Handler 复用同一套业务逻辑。
- 增加内容分享、@ 提及、收藏夹分组、不感兴趣和基础屏蔽能力的接口预留。
- 评论区支持分页、楼中楼展示和删除策略。
- 互动行为写入通知表，用户可在通知中心查看未读通知并标记已读。
- 增加基本风控：重复操作、频率限制、软删除或隐藏策略。

验收标准：

- 点赞、收藏、关注具备基础 toggle 行为，刷新后状态和计数保持一致。
- 评论和通知能在刷新后保持一致，且不会给自己的内容发送自通知。
- 后台能追踪关键互动指标。
- 社交互动接口具备移动端复用能力，后续可接入私信和分享链路。

M3.1 已完成：

- 通知中心页面/API：未读数、已读、分页、按类型筛选。
- 评论区基础增强：一级评论 cursor 分页、每条评论展示最近 3 条回复、登录用户可回复评论、回复通知写入被回复用户。
- 互动风控基础版：点赞、收藏、关注、评论/回复接入 Redis 优先的限流、目标冷却和重复内容保护；Redis 不可用时降级为进程内保护。
- 移动端互动 API：`POST /api/v1/notes/[noteId]/like`、`POST /api/v1/notes/[noteId]/favorite`、`POST /api/v1/notes/[noteId]/comments`、`POST /api/v1/users/[handle]/follow` 已按 M1.5 API contract 返回统一 envelope，并复用 Web 互动业务规则。
- 评论治理基础版：评论作者可软删除自己的评论，其他用户可举报评论，后台举报队列可将评论标记处理中、隐藏评论并解决、或驳回举报，并写入 `AdminAuditLog`。

M3.1 待补：

- 高级互动风控：异常频率识别、设备/IP 风险、黑名单、屏蔽和不感兴趣。
- 评论治理增强：举报详情页、删除/隐藏恢复、敏感词审核、评论举报移动端列表和审核批量处理。
- 移动端认证增强：当前 `/api/v1` 互动接口复用 Web session；M8 App 接入前需要补 token/session 持久化、刷新和设备维度风控。
- 收藏夹分组、分享链接、@ 提及和私信入口。

### M4：搜索和推荐

优先级：中高。

- 搜索先实现标题、正文、标签的关键词检索，再接入 pgvector 语义召回。
- 将搜索定位为“生活搜索”能力：支持搜索建议、热搜、历史搜索、话题/用户/笔记分类结果。
- 发布或更新笔记时生成 embedding，写入 `note_embeddings`。
- Feed 推荐结合 `scoreRecommendation` 的信号：语义相似度、标签匹配、互动、新鲜度、关注作者。
- Redis 缓存热门标签、首页推荐候选、搜索热词。
- 增加推荐解释字段，便于后台观察排序原因。
- 增加发现页信息架构：推荐流、关注流、话题榜、地点/同城入口和活动专题预留。

验收标准：

- 搜索结果能解释命中原因。
- 推荐流不是简单按发布时间排序。
- 未配置 `OPENAI_API_KEY` 时本地开发仍能运行，生产环境必须配置真实 embedding。
- 用户能围绕笔记、用户、话题进行基础搜索和发现。

### M5：内容治理和管理后台

优先级：中。

- 管理后台接入真实指标：新增用户、新增笔记、待审举报、搜索转化。
- 举报处理支持状态流转：OPEN、REVIEWING、RESOLVED、REJECTED。
- 审核动作写入 `admin_audit_logs`。
- 笔记支持隐藏、归档、恢复。
- 增加用户角色管理和封禁策略。
- 增加社区信任治理入口：内容质量标记、广告/软广识别、刷量风险、账号处罚和申诉预留。

验收标准：

- 管理员每次治理动作都有审计记录。
- 被隐藏的内容不会出现在公开 Feed 和搜索结果。
- 举报详情页能看到目标、举报人、处理历史和处理入口。
- 治理后台可以围绕内容、用户、评论和互动指标追踪风险。

### M6：生产化和质量保障

优先级：中。

- 增加 Playwright 端到端测试覆盖登录、发布、搜索、后台审核。
- 为推荐和搜索服务补单元测试。
- 增加环境变量校验，启动时明确缺失项。
- 补充错误边界、loading 状态、日志和基础监控。
- 优化图片策略，生产环境关闭 `images.unoptimized` 并配置可信远端图片域名或对象存储域名。
- 增加部署说明和数据库迁移流程。
- 增加基础压测和容量评估：使用生产构建测试首页、详情、搜索、登录、发布等核心路径，记录 RPS、P95/P99、错误率、数据库连接数和慢查询。
- 对热点写入做低成本改造：浏览量、曝光、点赞、收藏等计数支持 Redis 聚合或异步批量写回，避免每次请求直接写数据库。

验收标准：

- CI 至少运行 lint、typecheck、单元测试和核心 e2e。
- 生产环境配置不依赖本地默认密码。
- 常见失败路径可定位，有错误日志和用户可理解的提示。
- 有第一版容量基线和压测报告，明确单实例、数据库和缓存的主要瓶颈。
- 首页、详情、搜索等核心路径不会因为无分页、实时全表统计或热点写入在小规模公开测试时过早失稳。

### M7：国际化和多地区能力

优先级：中。

- 引入国际化路由和文案管理，至少支持 `zh-CN`、`en-US`。
- 将页面静态文案、表单提示、错误提示、后台状态文案抽离为 message dictionary。
- 为用户、笔记、标签保留 locale 字段或翻译表设计，支持内容按语言筛选和展示。
- 支持用户语言偏好、浏览器语言识别、URL locale 切换。
- 增加日期、数字、相对时间、货币和计数格式的 locale-aware 格式化。
- 后台支持按语言和地区筛选内容、举报和运营指标。
- 为 SEO 增加 `hreflang`、多语言 metadata、站点地图策略。

验收标准：

- `/zh-CN` 和 `/en-US` 能展示同一套核心页面，文案来自字典而不是硬编码。
- 用户刷新、复制链接、切换语言后仍能保持正确 locale。
- 主要表单、空状态、错误提示和后台状态都支持双语。

### M8：移动端 App

优先级：中。

- 先确定移动端技术路线：推荐 React Native + Expo，复用 TypeScript、业务 DTO、API contract 和设计 token。
- 为移动端补齐后端 API：Feed、详情、搜索、登录、注册、发布、上传、点赞、收藏、评论、关注、通知。
- 设计移动端信息架构：发现 Feed、搜索、发布、消息、我的、笔记详情、用户主页。
- 移动端导航参考生活社区主链路：发现、搜索、发布、消息、我的；发现页支持推荐、关注和话题入口。
- 支持移动端图片选择、压缩、上传进度、失败重试。
- 接入移动端认证持久化和刷新策略，避免复用 Web-only session 假设。
- 实现 push notification 的服务端通知队列和移动端接收流程。
- 增加离线/弱网策略：Feed 缓存、草稿本地保存、上传恢复。
- 建立移动端 E2E 或关键流程手工 QA 清单。

验收标准：

- iOS/Android 开发环境能启动并访问同一套后端。
- 移动端用户可以登录、浏览 Feed、查看详情、搜索、发布图文、点赞收藏评论。
- 移动端和 Web 的用户数据、笔记数据、互动数据保持一致。

### M9：跨端运营、增长和可观测性

优先级：中低。

- 建立 Web/App 统一埋点规范：页面浏览、搜索、曝光、点击、发布、互动、举报。
- 增加 A/B 实验框架，用于推荐权重、Feed 样式、发布流程优化。
- 接入跨端通知中心：站内通知、邮件、移动 Push 的统一模板和发送策略。
- 增加内容安全策略：敏感词、图片审核、垃圾账号识别、举报自动分派。
- 增加多端版本管理：Web release、App build、API version、数据库 migration 对齐。
- 增加数据看板：留存、活跃、发布转化、搜索转化、推荐点击率、审核 SLA。
- 建立容量和成本看板：RPS、并发连接、缓存命中率、慢查询、队列积压、对象存储/CDN 流量、错误预算。

验收标准：

- 核心用户路径有统一事件追踪，Web 和 App 可以区分来源。
- 后台能查看主要增长、推荐和治理指标。
- API 变更有版本策略，不会无意破坏移动端旧版本。
- 容量扩展有数据依据，而不是凭感觉增加服务实例或缓存层。

### M10：原生 App 体验和创作工具

优先级：中低。目标是从“能用的移动端”升级为接近真实内容社区 App 的体验。

- 完善移动端首页信息架构：推荐瀑布流、关注流、搜索入口、发布入口、消息、我的。
- 支持移动端沉浸式笔记详情：图片轮播、视频播放、评论抽屉、相关推荐、作者卡片。
- 增加原生交互体验：下拉刷新、无限滚动、图片预加载、离线缓存、骨架屏、手势返回。
- 扩展创作工具：多图发布、视频发布、封面选择、图片裁剪、滤镜、贴纸、文字、话题、地点。
- 增加草稿箱、自动保存、发布失败重试、上传进度、上传恢复。
- 增加创作者数据面板：曝光、阅读、点赞、收藏、评论、转粉、发布转化。
- 增加创作者中心：发布任务、内容质量建议、账号成长等级、认证状态和商业合作入口。
- 支持内容可见范围：公开、仅自己可见、草稿、隐藏、删除恢复。

验收标准：

- App 具备接近真实社区产品的底部导航和核心信息架构。
- 用户可以在移动端完成图文/视频创作、草稿保存、上传和发布。
- 移动端弱网和失败场景有明确状态提示和恢复路径。
- 创作者可以查看基础内容数据，数据和 Web 后台口径一致。

### M11：社交消息、电商、直播和商业化

优先级：低。目标是把内容社区扩展为内容消费、社交互动和商业转化闭环。

- 增加私信和会话系统：会话列表、消息收发、已读未读、屏蔽、拉黑、举报。
- 支持 @ 提及、站内分享、站外分享、收藏夹分组和用户关系推荐。
- 增加商品能力：商品卡片、商品详情、店铺、购物车、订单、支付、退款、售后。
- 支持笔记挂商品、达人带货、佣金结算、商家后台和商品审核。
- 增加“内容种草到交易”的轻量路径：笔记商品卡、评论求链接、同款推荐、商品收藏和购买转化追踪。
- 增加优惠券、活动页、专题页、榜单、签到、任务和营销投放位。
- 增加直播能力：直播间、弹幕/评论、直播商品橱窗、直播预约、开播通知。
- 建立商业化指标：商品点击、加购、下单、支付、退款、佣金、活动转化。

验收标准：

- 用户可以从笔记进入商品详情并完成一条最小交易链路。
- 私信、通知、分享和用户关系形成基础社交闭环。
- 商家、达人和平台管理员有清晰的权限边界和后台入口。
- 直播和营销活动可以先以 MVP 形态运行，不破坏内容社区主链路。

### M12：平台级治理、风控、合规和数据基础设施

优先级：低。目标是支撑 App 长期运营，而不是只完成单个功能页面。

- 扩展内容安全能力：敏感词、图片审核、视频审核、评论审核、垃圾内容识别。
- 扩展账号风控：异常登录、批量注册、刷量、刷评论、设备指纹、IP/地区风险。
- 增加治理工作台：举报队列、审核队列、申诉流程、处罚记录、审核 SLA。
- 补充隐私和合规能力：账号注销、数据导出、隐私权限说明、未成年人保护、内容分级。
- 建立数据平台：事件采集、曝光日志、点击日志、停留时长、完播率、推荐反馈。
- 增加 Feature Flag、灰度发布、A/B 实验、App Crash 监控、性能监控。
- 建立客服和反馈系统：帮助中心、用户反馈、工单流转、处理记录。
- 在真实流量增长后引入重型扩展能力：连接池/PgBouncer、读写分离、队列、CDN、分布式缓存、搜索服务、必要时再评估分库分表。

验收标准：

- 核心内容、账号、交易和直播风险可以被发现、拦截、审核和追溯。
- 运营、推荐、审核和商业化数据有统一事件口径。
- 新功能可以灰度发布并观察指标，出现问题可快速回滚。
- 用户隐私、账号注销、数据导出和未成年人保护有明确产品入口和处理流程。

## 技术原则

- 默认使用 Server Components。只有表单交互、浏览器 API、状态管理、事件处理需要 Client Components。
- App Router 的 `params` 和 `searchParams` 按当前 Next.js 16 文档使用 Promise 类型。
- 数据访问优先放到 `src/lib` 或未来的领域服务文件中，页面负责组装 UI。
- Prisma schema 是业务模型的事实来源，变更模型必须同步 migration、seed 和文档。
- 对象存储只通过服务端签发上传 URL，不把密钥暴露给客户端。
- Route Handler 和 BFF API 必须返回统一 DTO、错误码和分页结构，避免 Web 和 App 分叉。
- 当前阶段优先做可扩展边界，不提前做重型并发优化；但不能写出后续无法分页、无法缓存、无法异步化的接口。
- 推荐权重先保持简单可解释，等有真实行为数据后再做复杂模型。
- 管理后台所有修改类操作必须写审计日志。
- M1.5 后新增国际化文案不得散落在页面组件中，统一由 locale dictionary 或翻译资源提供。
- 移动端和 Web 共享 API contract，不共享不适合跨端的 UI 组件假设。
- API 要有向后兼容意识，移动端发布后不能依赖“所有用户立即升级”。
- 涉及 pgvector、`note_embeddings` 和向量索引的 migration 必须人工审查后再提交。
- 面向增长的列表默认要考虑分页、排序稳定性和索引，而不是先做无限制查询。
- 浏览量、曝光、互动、搜索日志等事件要通过统一入口写入，未来可以从同步 DB 写入替换为 Redis/队列而不改业务调用方。
- 电商、直播、私信和治理属于独立业务域，不能和笔记 Feed 查询混在同一层服务里。
- 交易、支付、未成年人保护、隐私和内容安全属于高风险能力，上线前必须补测试、审计和回滚方案。

## 风险和注意事项

- 当前页面展示和 seed 数据并不完全共用同一套数据源，切换到数据库时要统一字段映射。
- `NoteEmbedding.embedding` 是 pgvector 的 `Unsupported("vector(1536)")`，Prisma 不能直接用普通 create/update 写入，需要保留安全的 raw SQL 封装。
- Prisma migration 可能误生成删除 pgvector 索引的 SQL，涉及 `DROP INDEX` 或 `note_embeddings` 时不要直接提交。
- `next.config.ts` 目前为方便本地演示设置了 `images.unoptimized: true`，生产化前需要重新评估。
- 本地脚本使用默认数据库和对象存储密码，只能用于开发环境。
- 国际化会影响路由、metadata、缓存和 SEO，越晚引入迁移成本越高。
- 移动端 App 发布后 API 兼容成本会显著提高，必须在 M8 前明确版本策略和错误响应格式。
- 当前登录、注册、发布页仍是静态表单，接入真实提交时要同步补鉴权、表单校验、错误提示和测试。
- 浏览量、点赞、收藏等互动计数要避免刷新或重复请求导致异常累加。
- 如果 Redis、MinIO 仍然依赖手动启动，上传、缓存、限流和推荐候选测试会不稳定。
- 对标小红书级 App 是平台工程，不应在 M2/M3 阶段提前堆电商、直播和复杂商业化；必须先把认证、发布、互动、搜索推荐、治理和 API contract 打牢。
- 高并发优化不能完全等到项目开发完再想：MVP 阶段不需要读写分离、分库分表和复杂队列，但必须从现在开始坚持分页、服务分层、统一事件入口、上传边界和权限边界。
